## 2. Definition / 定义

### 2.1 PMBOK 7th Edition Definition / PMBOK 第7版定义

**Definition 2.1** (Project Monitoring - PMBOK 7th Edition)

Project monitoring is the process of tracking, reviewing, and reporting overall progress to meet the performance objectives defined in the project management plan.

**Key Activities / 关键活动**:

- **Performance Tracking / 绩效跟踪**: Tracking project performance
- **Progress Measurement / 进度测量**: Measuring project progress
- **Status Reporting / 状态报告**: Reporting project status
- **Change Control / 变更控制**: Controlling project changes
- **Risk Monitoring / 风险监控**: Monitoring project risks

### 2.2 ISO 21500 Standard Definition / ISO 21500 标准定义

**Definition 2.2** (Project Monitoring - ISO 21500:2012)

Project monitoring tracks and reviews project progress and performance.

## 3. Category Theory Perspective / 范畴论视角

### 3.1 Monitoring as Object / 监控作为对象

**Definition 3.1** (Monitoring Phase Object)

The monitoring phase $Ph_{mon} \in \mathbf{Phase}$ is an object:

$$Ph_{mon} = (Name_{mon}, State_{mon}, Milestones_{mon}, Deliverables_{mon})$$

### 3.2 Monitoring Morphisms / 监控态射

**Definition 3.2** (Monitoring Transition Morphism)

The monitoring-to-closure transition:

$$\tau_{mon \to close}: Ph_{mon} \to Ph_{close}$$

---

## 4. Properties / 性质

### 4.1 Basic Properties / 基本性质

**Property 4.1** (Monitoring Existence)

Every project has a monitoring phase:

$$\forall P \in \mathbf{Project}: \exists Ph_{mon} \in L(P)$$

**Property 4.2** (Monitoring Continuity)

Monitoring is continuous:

$$\forall t: \exists MonitorState(t)$$

## 5. Relations / 关系

### 5.1 Relations to Other Concepts / 与其他概念的关系

**Relation 5.1** (Monitoring → Execution)

Monitoring tracks execution:

$$Ph_{exec} \to Ph_{mon}$$

**Relation 5.2** (Monitoring → Closure)

Monitoring precedes closure:

$$Ph_{mon} \to Ph_{close}$$

## 7. Explanations / 解释

### 7.1 Intuitive Explanation / 直观解释

**Explanation 7.1** ("Dashboard" Metaphor)

Project monitoring is like a dashboard:

- **Gauges / 仪表**: Performance metrics
- **Alerts / 警报**: Risk indicators
- **Reports / 报告**: Status information
- **Controls / 控制**: Change management

### 7.3 直观解释配例 / Intuitive Explanation with One Example

**Example 7.3** (监控即仪表盘 + 一例 / Monitoring as Dashboard with One Example)

用「仪表盘」比喻：仪表=进度/质量/风险指标，警报=偏差与风险触发器，报告=周报/月报，控制=变更流程。例如 $C(State, Baseline)=True$ 当 EV、SPI、CPI 在阈值内；超出则触发 $\tau_{monitor \to exec}$ 的纠正或 $\tau_{monitor \to plan}$ 的基准变更。

## 8. Argumentation / 论证

### 8.1 Why Monitoring Exists / 为什么监控存在

**Argument 8.1** (Necessity Argument)

Monitoring exists because:

1. Projects need oversight
2. Oversight requires monitoring
3. Monitoring provides visibility
4. Visibility enables control
