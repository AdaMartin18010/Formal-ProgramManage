## 2. Definition / 定义

### 2.1 Transformation Path Definition / 变换路径定义

**Definition 2.1** (Project Transformation Path)

A project transformation path is:

$$Path(P_1, P_n) = [T_1, T_2, \ldots, T_{n-1}]$$

sequence of transformations from $P_1$ to $P_n$.

### 2.2 Framework Definition / 框架定义

**Definition 2.2** (Transformation Path Framework)

The transformation path framework is:

$$PathFramework = \{Path, Sequence, Parallel, Optimize\}$$

with paths, sequences, parallel paths, and optimization.

---

## 3. Category Theory Perspective / 范畴论视角

### 3.1 Path as Morphism / 路径作为态射

**Definition 3.1** (Transformation Path Morphism)

A transformation path is a morphism:

$$Path: P_1 \to P_n$$

composite of transformations.

### 3.2 Framework Properties / 框架性质

**Axiom 3.1** (Path Composition)

Paths compose:

$$\forall Path_1, Path_2: Path_1 \circ Path_2 = Path_3$$

---

## 4. Properties / 性质

### 4.1 Basic Properties / 基本性质

**Property 4.1** (Path Composition)

Paths compose:

$$\forall Path_1, Path_2: Path_1 \circ Path_2 = Path_3$$

**Property 4.2** (Path Validity)

Paths are valid:

$$\forall Path: Valid(Path)$$

### 5.1 Relations to Other Concepts / 与其他概念的关系

Paths connect projects:

**Relation 5.2** (Path → Transformation)

## 6. Examples / 例子

### 6.1 Sequential Path Example / 顺序路径例子

**Example 6.1** (Refactoring Sequence)

Consider sequential path:

$$Path(P_1, P_3) = [Refactor_1, Refactor_2]$$

sequential refactoring path.

### 6.2 Parallel Path Example / 并行路径例子

**Example 6.2** (Parallel Optimization)

Consider parallel path:

$$Path(P_1, P_2) = [Optimize_1 \parallel Optimize_2]$$

parallel optimization path.

## 7. Explanations / 解释

### 7.1 Intuitive Explanation / 直观解释

**Explanation 7.1** ("Journey" Metaphor)

Transformation path is like journey:

- **Start / 起点**: Starting project / 起始项目
- **Path / 路径**: Transformation sequence / 变换序列
- **End / 终点**: Target project / 目标项目

## 8. Argumentation / 论证

### 8.1 Why Transformation Paths Exist / 为什么变换路径存在

**Argument 8.1** (Connection Argument)

Transformation paths exist because:

1. Projects need connections
2. Connections require paths
3. Paths enable transformations
4. Transformations enable change

### 9.2 应用案例 / Application Case

**Case 9.2** (组合内项目演进的变换路径选择 / Transformation Path Selection for Portfolio Evolution)

某产品组合从「概念验证 $P_0$」到「量产 $P_n$」存在多条变换路径，如顺序路径 $Path(P_0,P_n)=[Refactor_1, Refactor_2, Optimize]$ 或含并行的 $[Optimize_1 \parallel Optimize_2] \circ Refactor$。运用 PathFramework 的 $Sequence$、$Parallel$、$Optimize$ 比较路径成本与风险，支撑组合内「先重构再优化」或「并行优化后重组」的决策。参见 [03-项目管理案例分析](../../Concept/13-综合实践概念/03-项目管理案例分析.md)、[03-项目变换关系网络框架](../../Concept/10-Transfer概念/03-项目变换关系网络框架.md)。
