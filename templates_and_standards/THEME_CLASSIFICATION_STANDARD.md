# 主题分类标准

## 一、标准概述

本文档定义了Formal-ProgramManage（正式程序管理）项目的主题分类标准，用于规范所有项目文件的内容组织和主题归属。所有分类标准对齐PMI PMBOK 7th Edition、ISO 21500:2012、ISO 31000:2018、PRINCE2 2017、CMMI-DEV等国际项目管理标准。

## 二、主题分类体系

### 2.1 一级主题分类（5大层次）

项目采用**5大层次**的知识体系结构：

1. **基础理论层** (Foundation Layer, FL) - 形式化基础、数学模型、语义模型等
2. **核心模型层** (Core Model Layer, CML) - 生命周期、资源、风险、质量模型
3. **验证理论层** (Verification Layer, VL) - 模型检验、定理证明、一致性检查
4. **应用模型层** (Application Layer, AL) - 传统行业、新兴技术、专业领域模型
5. **实现验证层** (Implementation Layer, IL) - 形式化实现、验证工具、一致性检查

### 2.2 二级主题分类

每个一级主题下包含多个二级主题，详见 `THEME_HIERARCHY_STRUCTURE.md`。

### 2.3 三级主题分类

每个二级主题下可进一步细分为三级主题，形成完整的主题层次树。

## 三、主题分类原则

### 3.1 分类原则

1. **唯一性原则**: 每个主题只能归属于一个一级维度
2. **层次性原则**: 主题分类必须遵循层次结构
3. **完整性原则**: 所有内容必须能够归类到某个主题
4. **一致性原则**: 相同类型的内容使用相同的分类标准

### 3.2 分类方法

#### 方法1: 按内容性质分类

- **基础理论层**: 形式化定义、数学建模、语义模型、形式化规范
- **核心模型层**: 生命周期模型、资源管理模型、风险管理模型、质量管理模型
- **验证理论层**: 模型检验、定理证明、一致性检查、形式化验证
- **应用模型层**: 行业应用模型、技术应用模型、专业领域模型
- **实现验证层**: 代码实现、验证工具、自动化系统

#### 方法2: 按项目结构分类

- **docs/01-foundations/**: 基础理论层
- **docs/02-project-management/**: 核心模型层
- **docs/03-formal-verification/**: 验证理论层
- **docs/04-industry-applications/**: 应用模型层
- **docs/05-implementations/**: 实现验证层

#### 方法3: 按国际标准分类

- **PMBOK 7th Edition**: 12个原则、8个绩效域、价值交付系统
- **ISO 21500:2012**: 39个过程、10个知识领域、5个过程组
- **ISO 31000:2018**: 风险管理框架、风险管理过程
- **PRINCE2 2017**: 7个原则、7个主题、7个过程
- **CMMI-DEV**: 22个过程域、5个成熟度等级

## 五、主题标签规范

### 5.1 主题标签格式

主题标签采用以下格式：

```
[维度代码]-[二级主题代码]-[三级主题代码]
```

例如：

- `FL-1.1-1.1.1` 表示基础理论层-形式化基础理论-项目定义
- `CML-2.1-2.1.1` 表示核心模型层-生命周期模型-启动阶段
- `VL-3.1-3.1.1` 表示验证理论层-形式化验证理论-模型检验
- `AL-4.1-4.1.1` 表示应用模型层-软件开发模型-敏捷开发
- `IL-5.1-5.1.1` 表示实现验证层-Rust实现-项目状态转换系统

### 5.2 层次代码

- **FL**: Foundation Layer (基础理论层)
- **CML**: Core Model Layer (核心模型层)
- **VL**: Verification Layer (验证理论层)
- **AL**: Application Layer (应用模型层)
- **IL**: Implementation Layer (实现验证层)
- **AP**: Applied Practice (应用实践)
- **CS**: Cognitive Science (认知科学)
- **PR**: Philosophical Reflection (哲学思辨)

### 5.3 主题标签使用

每个项目文件应在文件头部添加主题标签，格式如下：

```markdown
---
主题标签: [TF-1.1-1.1.1]
一级主题: 理论基础维度
二级主题: 微积分的价值与用途
三级主题: 作为"变化的语言"
---
```

## 八、主题分类维护

### 8.1 新增主题

当需要新增主题时：

1. 确定主题所属的一级维度
2. 确定主题所属的二级主题
3. 确定主题所属的三级主题（如适用）
4. 更新 `THEME_HIERARCHY_STRUCTURE.md`
5. 更新相关文件的主题标签

### 8.2 主题调整

当需要调整主题分类时：

1. 评估调整的必要性
2. 更新 `THEME_HIERARCHY_STRUCTURE.md`
3. 更新相关文件的主题标签
4. 更新项目结构映射关系

### 8.3 主题合并

当需要合并主题时：

1. 评估合并的合理性
2. 更新 `THEME_HIERARCHY_STRUCTURE.md`
3. 合并相关文件内容
4. 更新主题标签
